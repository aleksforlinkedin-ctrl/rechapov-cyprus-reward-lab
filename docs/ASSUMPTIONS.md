## Статус правил

Все рабочие наборы этого прототипа имеют статус `assumed`, а не `approved`. Удачная композиция и успешный тест вычислений не являются подтверждением условий акции компанией. `draft` сохраняет исходные данные и не исполняется. `assumed` допустим в review/demo; производственная граница должна отклонять его. `approved` требует внешнего подтверждения правил, а не переключателя в интерфейсе.

Продуктовые тексты — на английском. Переключение концепции, сценария, N, суммы и состояния — инструменты исследователя вне продуктовой модалки. Число этапов в продукте задаёт маркетолог, не игрок.

## Конфликты и принятая граница точности

| Вопрос | Буквальный источник | Рабочее решение |
| --- | --- | --- |
| S2 | €850 ставок, earned 20,000, «ещё €1,500». Сумма €850 + €1,500 = €2,350 не совпадает со следующим табличным порогом €1,000. | Именованное допущение о приоритете таблицы: €150 до следующего этапа. Следующий итог 50,000; прибавка +30,000. |
| S3 | €4,500 ставок, earned 250,000, «ещё €5,000». Это дало бы финал при €9,500, тогда как таблица говорит «выше €4,900». | Финальный порог не согласован. Только отдельный demo-набор принимает €5,000 и показывает остаток €500. |
| Значение coins в таблице | Формулировка про награду за каждое деление допускает сложение строк, но первые шесть строк дают 38,100 вместо 20,000 в S2. Первые одиннадцать дают 778,100 вместо 250,000 в S3. | Рабочая cumulative-модель: earned — итог последнего достигнутого этапа; increment = next total − earned. |
| Разрывы диапазонов | Для целых евро не описаны €1,491–1,499, €2,491–2,499 и €3,991–3,999. При cents есть дополнительные промежутки, например €9.50. | Непрерывные интервалы от нижних порогов — отдельное допущение, не исправленная raw table. |
| До первой строки | Raw table начинается с €1. | Для review сумма ниже €1 даёт 0 coins. |
| Desktop placeholder | В исходном шаблоне дочерний placeholder 256 px выходит из DetailsContainer 192 px. | Ограничение — внешний контейнер 448×192; ошибочная вложенная высота не наследуется. |

Буквальное `Above €4,900` при шаге €0.01 означало бы €4,900.01, а при целых евро — €4,901. Ни один вариант не утверждён и не используется как скрытый fallback.

## Именованные наборы

### `research_table_open_final`

Допущения: cumulative totals; table priority for S2; zero below first threshold; continuous intervals from lower thresholds. Точные пороги в minor units: `[100, 1000, 10000, 20000, 40000, 80000, 100000, 150000, 200000, 250000, 400000]`. Последний этап остаётся unresolved с известной исключительной нижней границей `490000`.

При €4,500 известны earned 250,000, next total 300,000, increment +50,000, count 11/12. `remainingMinor` и `localFraction` — `null`, не 0. При wager > €4,900 результат блокируется для review: правило финала уже может изменить earned. Такой результат нельзя публиковать как готовые продуктовые условия.

### `demo_assumption_final_5000`

Сохраняет четыре допущения выше и добавляет точный финальный порог €5,000 (`500000` minor units). В S3 remaining €500 и local fraction 50%. На €5,000 или выше: 300,000 coins, 12/12, complete, next отсутствует.

Рядом с demo/canvas, вне продуктовой модалки, остаётся пометка:

> Demo assumption: cumulative rewards, normalized lower thresholds, final threshold €5,000; subject to confirmation.

### Независимые синтетические конфигурации

Эти данные проверяют универсальность layout и модели; они не расширяют условия исходной акции.

| Набор | Полный список threshold EUR → cumulative coins | Контрольная точка |
| --- | --- | --- |
| `layout_n1` | 100→500 | До €100: 0/1; на €100: complete, 500 coins. Нельзя обещать 300,000. |
| `layout_n6` | 1→100; 50→1,000; 200→5,000; 800→20,000; 2,000→100,000; 5,000→300,000 | При €850: 20,000 earned, 4/6, +80,000, €1,150 remaining. |
| `layout_n12` | Полная 12-stage cumulative-последовательность с точным demo-финалом €5,000 | S1/S2/S3 принадлежат именно этой конфигурации. |
| Другие N от 2 до 11, кроме N=6 | Отдельный полный набор для каждого N: этап i имеет threshold €(i×100) и cumulative coins i×500 | Их максимум — N×500 coins. Это синтетические данные, не исходные условия; ожидаемые значения S2 для N=12 к ним не применяются. |

У каждого набора собственные идентификаторы и версия конфигурации. Сокращение N не выполняется через усечение исходной таблицы с сохранением обещания прежнего максимума.

## Дневной цикл и другие открытые вопросы

- Часовой пояс акции, точный конец дня и точный момент зачисления не заданы. При неизвестном периоде текст — `Resets daily`, без придуманного countdown.
- Заработанные сегодня coins ещё не являются доступным балансом. `Added tomorrow` объясняет задержку, не обещает конкретный час.
- Новый день с wager 0 не стирает вчерашнюю earned-запись. `Pending credit` и `credited` — независимые события; ноль таймера не зачисляет coins.
- Источник активного дня — серверный контекст либо фиксированный review fixture. Локальная полночь устройства не определяет день акции.
- Правила qualifying bets, размещённые/рассчитанные ставки, отмены, возвраты и активация участия не заданы. Нельзя обещать, что earned никогда не уменьшается.
- `View eligible games` — предлагаемый текст CTA. Целевой маршрут и каталог eligible games не определены; локальное действие служит только демонстрации интерфейса и не ведёт в выдуманный игровой или депозитный flow.
- Правило изменения `configVersion` в середине дня не задано. Смешивать версии внутри текущего периода нельзя.
- Нулевая прибавка между двумя корректными этапами допустима моделью; запрет zero-delta был бы отдельным бизнес-правилом.

## Что действительно известно о прошлом варианте

В предоставленном PDF есть 25k вместо 250,000 при €4,500, смешение next total и increment, микроподписи и `COINTS TODAY`. Это наблюдаемые проблемы показанных экранов. Причина отказа компании неизвестна. Варианты A/B/C сравнивают ясность текущей награды, ближайшей цели и дневного цикла; превосходство B или C ещё не доказано пользовательскими сессиями.
